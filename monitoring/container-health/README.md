# Docker container health → node_exporter textfile (z8g4)

Host-level tooling for z8g4. It's kept in the aibrarian repo, but it isn't part of the app.
It adds Docker state and healthcheck metrics to the existing `/opt/stacks/monitoring` stack
through node_exporter's textfile collector (`/opt/stacks/monitoring/node_textfile` → `/textfile`).
It adds no new Prometheus or Grafana service, and no extra scrape job: the metrics arrive with the
existing `host.docker.internal:9100` node job.

| File | Purpose |
|---|---|
| `docker-health-textfile.sh` | one `docker ps -aq` + one `docker inspect --format` call → atomically writes `docker_health.prom` (tmp + mv). No jq. |
| `docker-health-textfile.service` / `.timer` | systemd oneshot run every 30s |
| `docker-health-alerts.yml` | optional Prometheus alert rules |
| `test-fixture.tsv` | mock inspect output for dry runs (`MOCK_INSPECT=test-fixture.tsv OUTPUT=- ./docker-health-textfile.sh`) |
| `../grafana/aibrarian-containers.json` | dashboard (generated by `../grafana/build_dashboards.py`) |

## Metrics
Labels: `name, compose_project, compose_service, image`. The label values are escaped (`\` `"` newline).

- `docker_container_running` 0/1
- `docker_container_health_status{status="healthy|unhealthy|starting|none"}`: one-hot (`none` = no healthcheck)
- `docker_container_healthy`: 1 healthy, 0 unhealthy, 0.5 starting, -1 no healthcheck
- `docker_container_restart_count`: Docker RestartCount (restart-policy restarts)
- `docker_container_started_seconds`: last start as a Unix timestamp (0 = never started)
- `docker_container_oom_killed`, `docker_container_exit_code`
- `docker_health_textfile_containers`, `docker_health_textfile_last_run_timestamp`

## Install (on z8g4, from a checkout of this repo)
```bash
cd ~/aibrarian && git pull   # or wherever the repo is cloned
sudo install -m 0755 monitoring/container-health/docker-health-textfile.sh /usr/local/bin/docker-health-textfile.sh
sudo cp monitoring/container-health/docker-health-textfile.service /etc/systemd/system/
sudo cp monitoring/container-health/docker-health-textfile.timer /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable --now docker-health-textfile.timer
```
Verify:
```bash
systemctl list-timers docker-health-textfile.timer
sudo OUTPUT=- /usr/local/bin/docker-health-textfile.sh | head      # dry run to stdout
cat /opt/stacks/monitoring/node_textfile/docker_health.prom
curl -s http://192.168.68.52:9100/metrics | grep docker_container
curl -s http://192.168.68.52:9100/metrics | grep 'node_textfile_scrape_error'   # should be 0
```
Logs: `journalctl -u docker-health-textfile.service -n 20`.

If you'd rather use cron: `* * * * * root /usr/local/bin/docker-health-textfile.sh` in `/etc/cron.d/docker-health` (1-minute resolution only).

## Grafana
In Grafana (http://192.168.68.52:3000), go to Dashboards → New → Import → upload
`monitoring/grafana/aibrarian-containers.json` and pick the Prometheus datasource.
The uid is `aibrarian-containers` and the tag is `aibrarian`, so a tag-based playlist picks it up.
Re-importing the file overwrites the existing dashboard.
The cAdvisor CPU/memory panels use `... and on (name) (max by (name) (docker_container_running) == 1)`,
so stopped containers no longer show up.

## Optional alerts
Prometheus doesn't have `rule_files` configured yet. To enable the rules:
```bash
sudo mkdir -p /opt/stacks/monitoring/prometheus/rules
sudo cp monitoring/container-health/docker-health-alerts.yml /opt/stacks/monitoring/prometheus/rules/
```
Add the following to `/opt/stacks/monitoring/prometheus/prometheus.yml` at the top level. The path is the path
*inside* the container. Check the prometheus `volumes:` in `docker-compose.yml`: if
`./prometheus` is mounted at `/etc/prometheus`, it is:
```yaml
rule_files:
  - /etc/prometheus/rules/*.yml
```
If only the `prometheus.yml` file is mounted, add a volume `./prometheus/rules:/etc/prometheus/rules:ro`
and run `docker compose up -d prometheus`. Otherwise restart it with
`docker compose -f /opt/stacks/monitoring/docker-compose.yml restart prometheus`.
You can see the alerts at http://192.168.68.52:9090/alerts. Notifications need Alertmanager, which isn't set up.
